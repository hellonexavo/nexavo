# Premium Web Design

## Goal
Create interfaces that feel intentional, premium, modern, trustworthy, and production-ready.

Do not aim for "AI-looking" decoration.
Aim for clear hierarchy, strong usability, visual restraint, and polished execution.

## When to use
Use this skill when the task includes:
- redesigning an existing page;
- creating a new landing page;
- improving a hero section;
- improving visual hierarchy;
- refining typography;
- improving spacing;
- improving buttons or calls to action;
- improving portfolio presentation;
- improving booking or service UI;
- making a page feel more premium;
- fixing weak responsive design.

## Before designing
Inspect the existing page and related components before changing anything.

Understand:
- the page goal;
- the primary user action;
- the current design language;
- existing reusable components;
- current typography;
- current spacing;
- mobile behavior;
- existing animations;
- existing brand patterns.

Do not redesign blindly.

## Visual principles

### Hierarchy
Every page should clearly communicate:
1. what this is;
2. why it matters;
3. what the user should do next.

Avoid competing focal points.

### Typography
Use typography intentionally.

Prefer:
- strong heading hierarchy;
- readable body text;
- restrained font sizes;
- consistent line-height;
- sensible line length;
- clear contrast between primary and secondary text.

Avoid:
- oversized text with poor mobile behavior;
- too many font sizes;
- overly thin body text;
- weak contrast.

### Spacing
Use consistent spacing systems.

Prefer generous breathing room where it improves clarity.

Avoid:
- random margins;
- cramped cards;
- large empty areas without purpose;
- inconsistent section spacing.

### Layout
Prefer simple, strong composition over unnecessary complexity.

Use grids and alignment intentionally.

Avoid:
- arbitrary floating elements;
- overlapping content unless clearly intentional;
- decorative UI that harms readability;
- horizontal overflow.

### Color
Respect the existing YY Builds visual identity.

Use accent color deliberately.

Avoid:
- excessive gradients;
- too many accent colors;
- low contrast;
- decorative glow everywhere.

### Cards
Cards should exist only when they improve grouping or hierarchy.

Avoid turning every piece of content into a card.

### Buttons
Calls to action must be obvious.

Use:
- one clear primary action;
- secondary actions only when necessary;
- clear hover/focus/disabled states;
- sufficiently large touch targets.

Avoid excessive competing CTA buttons.

## Premium feel
A premium interface usually comes from:
- precise spacing;
- strong typography;
- controlled contrast;
- consistent radius;
- clean alignment;
- subtle depth;
- restrained motion;
- excellent mobile behavior;
- polished interaction states.

Do not confuse "premium" with:
- many gradients;
- excessive glassmorphism;
- constant animation;
- oversized headings;
- visual noise.

## Responsive behavior
Design mobile intentionally, not as an afterthought.

Check:
- navigation;
- hero layout;
- heading wrapping;
- buttons;
- cards;
- grids;
- forms;
- image cropping;
- spacing;
- sticky elements;
- overflow.

Prefer layouts that naturally adapt instead of requiring many breakpoint hacks.

## Interaction design
Use animation only when it improves understanding or perceived quality.

Prefer:
- subtle hover states;
- short transitions;
- meaningful entrance motion;
- clear interactive feedback.

Avoid:
- long animations;
- constant movement;
- scroll hijacking;
- unnecessary parallax;
- motion that delays interaction.

Respect reduced-motion preferences where appropriate.

## Conversion
For landing and service pages, always identify the primary conversion action.

Ensure:
- the value proposition is clear;
- the CTA is visible;
- supporting proof appears where useful;
- forms do not ask for unnecessary information;
- the user is never confused about the next step.

## Accessibility
Maintain:
- semantic structure;
- readable contrast;
- visible focus states;
- keyboard usability;
- descriptive labels;
- usable touch targets.

Do not sacrifice accessibility for aesthetics.

## Implementation
Reuse existing project components when appropriate.

Avoid adding new dependencies solely for visual effects.

Prefer maintainable CSS and React patterns.

Do not rewrite unrelated functionality just to achieve visual changes.

## Verification
After implementation, review the page at minimum for:
- desktop;
- tablet;
- mobile;
- overflow;
- text wrapping;
- CTA visibility;
- contrast;
- interactive states;
- broken layouts.

Run relevant available project checks.

## Final review
Before considering the task complete, ask:
- Does the page immediately communicate its purpose?
- Is there a clear primary action?
- Does it feel consistent with YY Builds?
- Does it look polished without looking overdesigned?
- Is mobile equally strong?
- Did any existing behavior break?
- Was the change verified rather than assumed?
